# Vector · 智能车实验室

使用 **Node.js + 原生 ES Modules + Canvas 2D** 的本地智能车模拟器。无需安装第三方依赖，无摄像头、无三维场景。保留空算法接口，另提供简单赛道的指定路线演示。

## 启动

需要 Node.js 20 或更新版本，在本目录执行：

```sh
npm start
```

打开 **http://127.0.0.1:3000**。停止服务按 `Ctrl+C`。`npm run dev` 可监听服务端文件变化，前端修改后刷新浏览器即可。

## 操作

- 左侧赛道：**拖动车身**重新放置，**拖动时滚轮**旋转（默认每格 15°）。放置会暂停仿真并归零双轮；不把拖动模拟成真实惯性冲击。
- 空白处拖动平移，滚轮以指针位置为中心缩放。下方工具支持放大、缩小、适应赛道、定位车辆。车辆可以移出图片，图片外使用配置的背景反射率。
- 点击工具栏“跟随”开启视角跟随，车辆移动时保持在画布中心，滚轮可继续围绕车辆缩放。手动平移或点击“适应赛道”会退出跟随；拖动车辆期间暂时停止跟随，松开后恢复。参数页可设置并保存默认跟随状态（`view.followCar`）。
- 右侧“手动调试”设置双轮有符号 RPM，点击**开始仿真**或按空格运行；负数倒转。勾选联动可同时调两轮。初始目标为 0，开始后需设置轮速才会移动。
- 右上角“模拟速度”可随时切换 0.5× / 1× / 2× / 4× / 8× / 16× / 32×，立即生效且不会重置仿真。物理步长与传感器采样间隔保持不变，通过增加每帧仿真步数加速；计时器、曲线时间和算法超时均按仿真时间计算。约 64 秒的演示在 16× 下约 4 秒跑完（实际速度受设备性能影响）。默认倍率和可选档位统一在 `simulation.timeScale` / `simulation.speedOptions` 配置，右上角修改后可到参数页保存。
- 暂停会冻结仿真时间与运动；停止双轮会立即暂停并归零；重置会恢复配置的初始位置、控制模式、轮速、随机种子以及算法私有状态。浏览器切到后台自动暂停。
- 红外数据位于右侧独立卡片，滚动下方数据/参数面板或切换标签时始终可见。红外图显示每路反射率、命中、阈值，通道从车体左向右编号。最多支持 64 路；空间不足时自动缩窄柱宽和间隙、隐藏数值与编号，将全部通道显示在卡片内。鼠标悬停仍可查看通道编号与反射率，空间恢复后自动显示标签。
- 惯导显示全部九轴数据。点击加速度、角速度或磁场数据行可切换三轴时序曲线，航向盘用二维指针表示航向真值。
- 参数页**应用并重置**只影响当前页面；**保存到配置文件**写回根目录 `config.json`，下次启动仍有效。两者都会重置仿真。修改服务端口/主机需重启 Node 服务。

## 统一配置

**所有可修改的仿真参数和初始状态均集中在根目录 `config.json`。** 右侧提供常用数值设置，以及完整 JSON 编辑器（包含算法参数、初始轮速等）。物理尺寸和位置统一使用 **mm**，内部时间为秒。以下是配置分组：

| 分组 | 设置 |
| --- | --- |
| `server` | 本地监听主机、端口（默认 127.0.0.1:3000） |
| `track` | `image` 赛道相对路径、图片物理宽度、图片外反射率 |
| `vehicle` | 车身长宽、初始 X/Y/航向角 |
| `wheels` | 直径、宽度、车身间隙、最大 RPM、一阶响应时间 |
| `infrared` | 数量、模组宽度/厚度、与车头净间距、采样半径、阈值、亮/暗检测、噪声 |
| `imu` | 重力、世界磁场向量、三类传感器各自的噪声标准差 |
| `simulation` | 物理更新频率、传感器采样频率、倍率、最大帧时间、随机种子、轨迹上限 |
| `control` | 初始模式 `manual` / `algorithm`、双轮初始目标 RPM |
| `algorithm` | 模块路径、传给算法的任意 JSON 参数对象 |
| `view` | 缩放上下限、缩放灵敏度、旋转步长、画布留白、网格间距、叠加层、曲线历史、面板刷新率 |

更换赛道只需修改：

```json
"track": {
  "image": "复杂赛道.png",
  "widthMm": 2500,
  "backgroundReflectance": 0.03
}
```

图片支持 PNG / JPG / WebP / SVG，放在项目内，可用 `tracks/example.png` 等相对路径。图片高度按原始宽高比推导；`widthMm` 决定图中白线相对于车体和红外间距的物理尺寸。在参数页的“赛道图片”下拉框中选择简单或复杂赛道，再点击“应用并重置”或“保存到配置文件”。其他路径可选择“自定义图片路径…”后输入。随项目提供的简单、复杂赛道均可直接使用。

## 模型约定

- 世界坐标 X 向右、Y 向下；车体 X 向前、Y 向右，航向 0° 朝右、90° 朝下，**顺时针为正**。采用屏幕平面约定，接入硬件算法时请按实际 IMU 轴向变换。
- 车身为矩形，双轮轮轴位于车身纵向中点。左右轮中心距为 `vehicle.widthMm + wheels.widthMm + 2 × wheels.gapMm`，轮径会同时影响图形大小和运动速度。
- 红外模组位于车头前方，`gapMm` 是车头前缘到模组后缘的**净间距**。传感器处于模组宽度的 N 个等分单元中心（单路在中心）。红外采样点与图中显示的位置一致。
- 红外反射值取原图 RGB 亮度的加权值（0.2126 R + 0.7152 G + 0.0722 B），采样半径 > 0 时在中心和周边共 9 点平均，再叠加高斯噪声并限制到 0～1。透明像素与图片外反射率混合。亮线模式 `>= threshold` 命中，暗线模式 `<= threshold` 命中。
- 差速模型：`v = (vL + vR) / 2`，`ω = (vL - vR) / 轮距`；按圆弧解析积分。一阶电机响应，零响应时间表示理想电机。模拟固定物理步长，传感器单独按采样率更新；采样频率不能超过物理更新频率。
- 加速度计：X 为纵向加速度，Y 为向心加速度 `vω`，Z 为重力；单位 **m/s²**。陀螺仪 X/Y 为 0，Z 为角速度，单位 **rad/s**。磁力计把世界磁场旋转到车体系，单位 **μT**。全部轴均支持独立类别噪声。水平约束下滚转和俯仰固定为 0。
- IMU 独立于控制策略持续采样，算法即使不用 IMU，界面也正常显示。噪声采用固定种子，重置后相同控制输入可复现。
- 当前模型未包含打滑、碰撞、车身倾斜、IMU 漂移/融合算法和比赛计分。图片上的元件仅影响像素采样，未实现语义识别。

## 接入寻路算法

[public/algorithms/controller.js](public/algorithms/controller.js) 保留为**零速空实现**。当前配置默认启用 `public/algorithms/route-demo.js` 指定路线演示。模块导出工厂函数 `createController()`，返回同步更新函数；重置仿真重新调用工厂，方便清空 PID 等状态。

```js
export function createController() {
  // 在这里保存算法的私有状态。
  return function update(state, dt, parameters) {
    // 在这里实现策略，读取 state.infrared / state.imu。
    // 保留空实现，默认不行驶。
    return { leftRpm: 0, rightRpm: 0 };
  };
}
```

`state` 是隔离快照，包含：

```js
{
  time,                          // s
  pose: { xMm, yMm, headingRad },
  motion: { speedMps, angularVelocityRadSec, accelerationMps2 },
  wheels: { leftRpm, rightRpm, leftAngleRad, rightAngleRad },
  infrared: [{ index, lateralMm, xMm, yMm, reflectance, detected }],
  imu: {
    accelerometer: { x, y, z },   // m/s²
    gyroscope: { x, y, z },       // rad/s
    magnetometer: { x, y, z }     // μT
  }
}
```

`dt` 为固定物理步长，`parameters` 来自配置的 `algorithm.parameters`。传感器保持最近一次采样值。返回的 RPM 自动限幅；返回非法数值或抛出异常会立即停机并提示。不要返回 Promise。

测试不同方案时，在 `public/algorithms/` 新建模块，将配置的 `algorithm.module` 改为 `/algorithms/xxx.js`，应用或刷新页面后切到“算法接口”并开始运行即可。控制策略需要包含自己的启动/前进逻辑。

## 5 路红外 + 六轴 IMU 路线演示

当前 `config.json` 已设置简单赛道、5 路红外、算法模式和演示模块。运行 `npm start`，刷新页面后点击“开始仿真”，无需调整轮速。启动时静止 0.6 秒估计陀螺仪零偏；偏斜或偏离线时先原地扫描找线，再低速对准。完成后自动暂停并归零双轮。再次演示先点“重置”。

按用户标注的路线行驶：发车区向右 → 中左竖线向上 → 上边向右 → 右侧向下 → 右下向左 → 中右竖线向上 → 上边向左 → 左侧向下 → 左下向右返回发车区。路线有 9 个路段、8 次直角转向；回放测试约需 63～67 秒，正常转向阶段约 0.83～1.07 秒（不含减速接近路口）。

**输入约束由模拟器执行**：`algorithm.inputProfile = "ir5-imu6"` 时控制器只收到 `time`、`sampleTime`、5 路 `index/reflectance/detected`、加速度计 XYZ 和陀螺仪 XYZ。真实位置、航向真值、真实轮速、传感器世界坐标和磁力计完全不传给控制器。界面中的航向盘/位置仍是用于观察的仿真真值，控制器无法读取。六轴模式隐藏磁场显示；其余通用算法可使用 `inputProfile = "full"` 恢复完整观测。

演示采用**已知路线拓扑**，由 5 路红外触发路口操作：连续横向命中或持续断线后减速，把前置模组检测到的位置移至轮轴附近，再按路线指定方向扫描。元件横线与短断线先桥接；侧向没有目标线时回正继续寻找。`branch` 表示选择支路，`end` 表示直行优先、到末端才拐弯。没有固定的路段长度表，也不会因“估计已走够一段距离”就推进路线。

转向时陀螺仪辅助判向、减速和排除原来的线，**必须连续两次新的红外采样确认目标线居中，且转动已稳定，才能出弯**。转过 90° 本身不能推进路线。出弯后保留入弯基准加相对转角，再由红外细调，避免把斜着扫到线的瞬时方向当作新直线。起步尚未建立可靠方向时丢线会重新扫描，避免把发车区文字误触发当成赛道后高速盲走。

相对运动估计来自自身轮速指令和轮径/轮距/电机响应标定，用于模组到轮轴的局部前移、短距断线桥接和最后相对起点停车；不读取实际轮速，也没有编码器或 GPS。陀螺仪积分辅助航向，并用指令模型预测角速度跟踪零偏；加速度计输入保留，本演示未用其做距离双积分。发车区没有唯一的红外终点标记，因此最后停车仍依赖累计相对估计；当前无打滑模型中的误差不能代表真实车辆定位精度。持续丢线、无法回正或总时长超限会安全停机。

所有路线和调参保存在 `config.json` 的 `algorithm.parameters`：`route` 仅含名称、相对转角 `turnDeg` 和路口类型 `turnAt`；`drive` 是车辆静态标定值，改变车体、轮径、轮距、模组位置或电机响应时需同步修改。`cruiseRpm` / `approachRpm` 控制直行与路口速度，`maxTurnRadSec` 控制快速扫描，`confirmSamples` 控制红外连续确认次数，其余为循线、搜线和停机阈值。路线适用于简单赛道的当前拓扑及发车线附近，未实现未知赛道探索，也不能直接用于复杂赛道。恢复空算法可将 `algorithm.module` 改回 `/algorithms/controller.js`、`inputProfile` 改为 `full`。

`npm test` 包含真实赛道 PNG 回放：保持加速度计和陀螺仪噪声标准差均为 0.02，5 个种子 × 13 种发车角度/横向偏移组合共 65 个场景，包含 ±25°、±15 mm 的组合偏移，全部完成指定顺序的 8 次转向，最大停车偏差约 24.1 mm。另验证发车纵向平移 ±100 mm、赛道物理比例变为 0.8 / 1.2，以及转向中强制屏蔽全部红外时不得仅凭陀螺仪出弯。独立测量器可读取真值，控制器仍只有受限传感器输入。

运行 `npm run demo:check` 可快速回放一遍，生成 `test-results/route-report.json`（路口事件、红外确认、转向耗时）和 `test-results/route-trace.svg`。这里的“完成”指执行指定路线并回到发车区停车；模拟器尚未实现比赛官方计分或元件识别裁判。
